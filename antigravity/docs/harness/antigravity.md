# pstack in Antigravity

Read this adapter and `shared-memory.md` in this directory once per session before following a bundled skill or agent. These are harness mappings, not permission grants. User instructions, the actual tool schema, sandbox restrictions, and confirmation requirements always win. `<pstack>` is this generated package's root, two directories above this file. Never infer capability from a model name.

## Tools and agents

- `Task`: use `invoke_subagent` (Antigravity's native subagent tool; it runs asynchronously and wakes the parent when done, so never poll with `sleep` or loops). When a step specifically requires another provider's model and the host exposes `delegate_task` + `orchestrator_capabilities` (for example in T3 Code), call `orchestrator_capabilities` once first and pass only supported fields. Otherwise do the work with `invoke_subagent` or sequentially and disclose that independent or cross-provider verification was unavailable.
- `poteto-agent` and `comment-sicko`: this package ships Antigravity-compatible agent files at `<pstack>/agents/poteto-agent.md` and `<pstack>/agents/comment-sicko.md` (`model: inherit`, `subagent: true`, `mainAgent: false`). Invoke them with `invoke_subagent` (`TypeName: "poteto-agent"` or `"comment-sicko"`) when registered in the session; otherwise invoke `TypeName: "self"` and include `<pstack>/agents/<name>.md` plus the absolute path to `<pstack>/skills/poteto-mode/SKILL.md` in `Prompt`. Start every worker kickoff with `Read <pstack>/skills/poteto-mode/worker.md before anything else.` and ensure every worker reads this adapter and `shared-memory.md` too. Never search another product's plugin cache.
- `generalPurpose`: use `invoke_subagent` with `TypeName: "self"`.
- `readonly: true`: use `TypeName: "research"` when read-only local inspection without network or MCP access suffices; otherwise use `TypeName: "self"` with an explicit read-only brief and inspect `git status` and `git diff` afterward (a brief is not an OS sandbox). `readonly: false` maps to `TypeName: "self"`.
- `environment: "cloud"` / `"local"`, `cloud_base_branch`, `run_in_background`, `file_attachments`, and `resume`: never pass Cursor-only fields. Map `environment: "cloud"` to `Workspace: "share"` (shared-repo worktree) or `"branch"` (isolated clone) on `invoke_subagent`, or `isolation: "worktree"` on `delegate_task` when exposed; name any `cloud_base_branch` in `Prompt` so the worker checks it out in its isolated workspace. Map `environment: "local"` to `Workspace: "inherit"` (never switch a shared working tree's branch under another writer). Omit `run_in_background` (`invoke_subagent` is already async). List `file_attachments` paths in `Prompt`. For `resume`, use `send_message` with the live subagent's `conversationId`, or spawn a fresh subagent with the prior result pasted into `Prompt`.
- `AskQuestion`: use `ask_question` for multi-choice decisions when present and appropriate; otherwise concise plain text. `todolist`: keep a short maintained checklist in replies or a task artifact; do not invent an absent `TodoWrite` tool.
- `/name` (Run another pstack skill): read and follow `<pstack>/skills/<name>/SKILL.md`, first checking the project override described in `shared-memory.md`. When telling a user to invoke a discovered Antigravity plugin skill, use `/<name>` (not `/pstack:<name>`).
- Resolve bundled relative references from the original skill's location inside `<pstack>`. `Read`, `Edit`, `Write`, `Grep`, `Glob`, `Bash`, and `Shell` map to the actual available file, search, and command tools (`read_file`, `edit_file`, `write_file`, `run_command`, or IDE equivalents such as `view_file`, `grep_search`, `find_by_name`). Shell scripts need an installed compatible shell. On Windows PowerShell, do not pretend a POSIX Bash command is PowerShell.

## Models and setup-pstack

Read project `.pstack/models/antigravity.md` if it exists before using role defaults. `pstack-models.mdc` and `~/.cursor/rules/pstack-models.mdc` map to that file in Antigravity. Do not read or overwrite Claude's `~/.claude/rules/pstack-models.md` or Codex's `.pstack/models/codex.md`.

In Antigravity `invoke_subagent`, `Model` accepts only `inherit`, `flash_lite`, `flash`, or `pro`. Never pass Cursor slugs (`claude-*`, `gemini-*`, `grok-*`, `gpt-*`) to `invoke_subagent`. Map high-reasoning roles (`feature, refactoring`, `bug-fix`, `perf-issue`, `hillclimb`, `judgment and prose`, `swarm workers`) to `pro` or `inherit`, fast/cheap mining roles (such as `/recall` transcript fan-out) to `flash` or `flash_lite`, and `auto` or `inherit-parent` to `inherit` (or omit `Model`). When `delegate_task` and `orchestrator_capabilities` are exposed by the host, detect real provider/model IDs via `orchestrator_capabilities` and use only confirmed values; never invent slugs or switch providers unasked.

For `/setup-pstack`, keep the upstream role names and budget workflow, write plain Markdown without MDC frontmatter to `.pstack/models/antigravity.md`, and use only model tiers or confirmed provider/model values exposed by the current session. Never modify global `~/.gemini/` configuration to make a role work.

Keep the fan-out size when several reviewers run on the same model family, and label that honestly as same-model review. If a step requires a different-vendor judge and no other vendor is exposed and authorized, mark that cross-model check unperformed rather than claiming cross-vendor verification. Fallback reasoning does not authorize an extra paid provider.

## Paths and history

- `.cursor/skills/` maps to project `.claude/skills/`. Follow `shared-memory.md` for edits/overrides and user-scoped choices. Do not create duplicate mutable overrides in `.agents/skills/` or `~/.gemini/config/skills/`.
- `.cursor/rules/*.mdc` and always-applied project rules use Claude's existing project rule file (`CLAUDE.md`, with the `AGENTS.md` fallback described in `shared-memory.md`); model preferences are the exception above. Antigravity also natively discovers `GEMINI.md` and `AGENTS.md`: read `GEMINI.md` if present, and report conflicts instead of silently overwriting or duplicating `/correct`'s table across files. Never turn a rule into a permission grant.
- `~/.cursor/plugins/` and `.cursor-plugin/plugin.json` refer to this installed package (`~/.gemini/config/plugins/pstack/` or workspace `.agents/plugins/pstack/`) and its `plugin.json`, not another product's cache.
- A repository GitHub URL (`https://github.com/cursor/plugins/blob/main/pstack/<path>`) for a file included in this bundle maps to `<pstack>/<path>`. Do not fetch the upstream version over a project override.
- `agent-transcripts` and `~/.cursor/projects/` do not map to a guessed Cursor directory. In Antigravity, the current run's own transcript is at `<appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl` (and `transcript_full.jsonl`) when exposed in the session context. Use only the active conversation and history explicitly exposed/authorized by the host for this workspace. If inaccessible, use a labeled digest and report transcript-based audits as unverified. Never scan all projects, `~/.gemini/`, or `~/.claude/`, or bypass a denied path. Native Antigravity, Claude, and Codex chat histories are not shared by this adapter.

## Features outside Antigravity

Cursor Automations (`api2.cursor.sh/automations`, routines, `update_state`), Bugbot startup/configuration, Cursor cloud-agent dashboards, and Cursor's built-in PR tool are Cursor-only. When a step needs one, skip it with one line (`Skipped in Antigravity: <step>. <reason>.`) unless a genuine host equivalent is exposed and authorized:

- `/loop` / recurring schedules: use `schedule` (or host `schedule_task`) only when explicitly requested and exposed; otherwise report unavailable.
- `SendToUser` secret requests: use `request_secret` only when exposed by the host; otherwise report unavailable and never ask for automation secrets in plain chat.
- Bugbot comments: read ordinary Bugbot GitHub comments with an available forge tool (`gh`).
- PR operations: use `gh` (and host PR link/watch tools when exposed) only if installed, authenticated, and authorized.
- Multi-agent orchestration: Antigravity's `run_workflow` may be used for scripted fan-out when requested; do not call the native `swarm` tool unless the user explicitly invoked `/swarm` or a swarm is already active — pstack's `/swarm` skill fans out via `invoke_subagent` by default.

The optional `deslop`, `control-cli`, and `control-ui` skills come from `cursor-team-kit` and are bundled when this package is built. They are instructions, not a Cursor SDK. Browser (`preview_*` or local Playwright/CDP), terminal, GUI, and screenshot access still depend on the host. Missing tooling is a verification limit, not a successful check. `/create-skill` maps to explicit Antigravity skill authoring, not an invented built-in command.
